# Security checks and tests

Generated by `uv run python scripts/gen_checks_doc.py` from the rule tables in the code; regenerate it after adding or changing a check (`tests/test_new_checks.py` fails when a rule is missing here).

Every check is read-only towards the target: GET, HEAD, OPTIONS and TRACE only (POST only for the benign upload test on the aggressive profiles), in scope only, never following redirects, never downloading files, and never sending denial-of-service traffic. Findings are leads, not proof.

## Where each kind of check runs

| Layer | What it tests | Code | Runs in |
|---|---|---|---|
| DAST (native engine) | the running website | `src/scopeguard/engine.py` (`Scanner`) | isolated child interpreter with audit hooks (`src/scopeguard/sandbox.py`, `worker.py`) |
| Custom probes | planned extra checks on the website | `src/pentest_agent/tools/probe_runner.py` | the agent (httpx client with the network policy and 429 handling) |
| Website JavaScript SAST | the site's own scripts and inline JS | `engine.JS_RULES` | the DAST engine (`Scanner.sast`, in its sandbox) and the sandbox check (Kubernetes Job; in-process fallback) |
| Source-code SAST | your uploaded / git code | `src/scopeguard/codecheck.py` (`BACKEND_RULES`, `scan_routes`, `scan_file_level`) | Kubernetes Job (or the process sandbox); code is never run |
| Coding standard + ruff lint | Python files of your code | `src/scopeguard/codestyle.py` | same sandbox, parsed with `ast` / `tokenize`, never executed |
| Archive safety | the uploaded .zip itself | `src/scopeguard/archive.py` | inside the sandbox |

Profiles (`engine.PROFILES`): `quick` = crawl + passive checks only; `standard` adds safe active checks; `aggressive` / `auth_deep` add payload variants, time-based checks and upload tests.

## Custom probes (`src/pentest_agent/tools/probe_runner.py`)

The LLM (or the built-in plan without one) picks up to 16 probes from this fixed list; hand-written code runs them with GET or OPTIONS only. Timeouts are retried with tenacity (up to `PROBE_MAX_ATTEMPTS`).

| Probe | Reports | Needs a parameter |
|---|---|---|
| `security_headers` | missing HSTS, CSP, X-Content-Type-Options, Referrer-Policy, clickjacking protection | no |
| `cors` | a reflected untrusted Origin, or wildcard origin with credentials | no |
| `cookie_flags` | cookies without Secure, HttpOnly or SameSite | no |
| `http_methods` | methods advertised by OPTIONS (informational) | no |
| `reflected_marker` | a harmless marker echoed back from a query parameter (not proof of XSS) | yes |
| `information_disclosure` | stack traces and verbose framework errors in the body | no |
| `cache_control` | cookie-setting / authenticated responses without no-store / private | no |
| `server_banner` | server / framework versions in Server, X-Powered-By and similar headers | no |
| `csp_weakness` | unsafe-inline (without nonce/hash), unsafe-eval, wildcard script sources, open object-src | no |
| `directory_listing` | auto-generated file indexes | no |
| `open_redirect` | a query parameter that redirects to an outside host | yes |
| `mixed_content` | http:// scripts, styles, frames (medium) or images / media (low) on an HTTPS page | no |
| `insecure_transport` | the page answers on plain HTTP without redirecting to HTTPS | no |

## Automated tests (`tests/`)

Other gates: `uv run ruff check src tests` (lint), `uv run python -m scopeguard.cli --simulate` (all planted issues found), `uv run golden-check --allow-no-llm` (data drift) and `uv run pentest-audit verify` (audit chain).
